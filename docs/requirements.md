# 产品需求

状态：已确认（2026-09-11）  
版本：方案 v0.1

## 1. 背景与目标

Pi 允许用户在 Agent 工作期间继续输入消息，但 steering 和 follow-up 都会进入主
任务执行流，无法满足“在不影响当前任务的情况下了解进度”的需求。

本项目提供一个独立 Pi Extension。Extension 加载后自动观察当前 Pi 实例中的每个
用户任务，并允许用户通过 `/status` 旁路查询。

成功标准不是生成精确的完成百分比，而是用可验证信息回答：

1. 当前任务是否仍在运行；
2. 当前正在进行什么活动；
3. 最近完成了哪些工具动作；
4. 工作区相对任务开始时发生了什么变化；
5. 若存在长时间命令，相关候选进程是否仍存活；
6. AI 根据这些证据推断当前阶段、可能剩余事项和风险。

## 2. 产品原则

1. **加载即观察**：观察所有任务，无需手动开启或任务主动注册。
2. **查询不介入**：状态命令不成为主 Agent 的消息、steering 或 follow-up。
3. **Skill 无关**：不依赖 `project-development-orchestrator` 或其他 Skill 写状态。
4. **中文优先**：说明、标题、状态和警告尽可能使用中文；技术标识保留英文。
5. **事实与推断分离**：Pi 事件、工作区变化、候选进程关联和 AI 推断分区展示。
6. **诚实降级**：无法获取的信息显示“未知”及原因。
7. **轻量和安全**：默认内存存储、有限历史、截断和脱敏，不污染被观察项目。
8. **不输出百分比**：进度用阶段、活动、可能已完成、可能剩余、风险和置信度表达。

## 3. 用户任务定义

产品展示的“任务”不是单个 `agent_start → agent_end`，而是一个用户目标的观测
容器；Pi 的低层 `agent_start → agent_end` 称为 Execution Run。同一个 Execution Run
可能先后承载原任务和实际开始执行的 follow-up 新任务，因此任务与 Execution Run
不是一一归属关系；任务只记录自己在 Run 内观察到的执行区段和共享 Run ID。

- Pi 空闲时提交并触发 Agent 的普通输入、Skill 或 Prompt Template：新任务。
- Steering：归入当前任务，作为方向调整事件，不新建任务。
- Follow-up 入队：只作为待执行项；真正作为后续 user turn 交付给 Agent 时，先结束并
  归档前一任务，再建立新任务。`one-at-a-time` 每次实际交付建立一个新任务；`all`
  模式下一次合并交付的批次建立一个新任务，并保留批次内各条来源。
- 自动 retry、overflow recovery 和自动 compaction 后继续：仍属当前任务。
- 工具调用和并行工具批次：归入事件发生时的当前任务执行区段。
- `/status` 自身：不是任务，也不写入被观察任务时间线。
- abort、不可恢复失败或正常结束：结束当前任务并进入历史。

Extension 内部为每个任务生成本地 Task ID，为每次 `agent_start → agent_end` 生成
Execution Run ID，并为任务记录 Run 内区段。若 Pi 事件不足以可靠确认 follow-up 的
实际交付边界，必须标记部分观测及原因，不得伪造边界。

## 4. 历史保留

每个 Session 保存：

- 最多 1 条当前活跃任务；
- 最近 3 条已结束任务，当前任务不计入 3 条限制。

第 4 条已结束任务产生时，按结束时间淘汰最早的一条。成功、失败和中止采用相同
FIFO 规则。首版默认仅内存保存；退出、reload 或 Session runtime 被替换后允许丢失，
但必须在中途加载时标注“观测不完整”。

## 5. 正式命令

```text
/status
/status help
/status timeline
/status files
/status analyze
/status history
/status <1|2|3>
/status <1|2|3> timeline
/status <1|2|3> files
/status <1|2|3> analyze
```

参数首尾空格忽略、多个空格等价、英文子命令大小写不敏感。不支持含糊缩写；多余
参数和未知子命令必须给出中文错误并提示 `/status help`。

明确不提供：

```text
/status watch on|off
/status raw
/status process
```

观察始终开启；内部调试通过显式环境变量和安全日志完成；有价值的候选进程信息
自动合并到 `/status`。

## 6. `/status` 默认页面

默认显示当前活跃任务；无活跃任务时显示最近结束的任务。页面按可用性包含：

- 任务状态、开始时间、已运行时间、最近事件、观测完整性；
- 当前模型活动或一个/多个活跃工具；
- 工具名称、已脱敏和截断的参数摘要、持续时间及结果；
- 存在可靠候选时的 PID、命令、存活状态、运行时长、CPU/内存和关联可信度；
- 工作区变化数量与前若干文件；
- 最近若干关键活动；
- 数据限制和归因警告。

字段不可获取时局部显示“未知”或省略无价值空区域，不能让整个命令失败。

## 7. 详细视图

### `/status timeline`

展示较完整的任务活动时间线，包括任务开始、模型处理、工具开始/结束、steering、
follow-up 队列变化、retry、compaction、UI 等待、abort 和 settled。并行工具按各自
Tool Call ID 和真实事件时间呈现，不伪造串行顺序。

### `/status files`

区分：

1. 任务开始时已存在的工作区状态；
2. 任务运行期间相对基线新出现或进一步变化的内容；
3. 查询时的当前工作区状态。

展示 staged、tracked 和 untracked 分类。措辞只能说明任务期间工作区观察到变化，
不能断言由当前 Agent 产生。非 Git 仓库明确降级。

### `/status analyze`

通过与主 Agent Loop 隔离的模型调用，默认用当前已配置模型分析观测快照。输出：

- 推断阶段；
- 观察依据；
- 可能已经完成；
- 当前可能正在进行；
- 可能剩余；
- 风险、阻塞和未知；
- 置信度。

必须显著声明这是 AI 推断；不得把推断写入主 Session；支持取消、超时和调用失败；
会产生额外模型调用和费用。

### `/status history` 与编号

`history` 显示当前 Session 最近 3 条已结束任务。`1` 是最近结束，`3` 是保留范围内
最早。编号可与 `timeline`、`files`、`analyze` 组合。

### `/status help`

显示全部正式语法、示例、自动观察、3 条历史限制、工作区归因限制及 AI 成本提示。
该命令不查询 Git、进程或模型，应立即返回。

## 8. 数据与安全

默认不保存或展示：

- 完整环境变量；
- 完整 Prompt 或 Assistant 响应；
- 完整 diff；
- 无界工具输出；
- API Key、Token、密码、私钥等凭证。

时间线和文本字段均设容量上限。命令参数、错误摘要、AI 输入和调试日志必须经过
统一截断与脱敏。`/status` 查询不得修改项目文件。

## 9. 首个可用版本范围

首个可用版本必须完整实现本文件所述命令、自动观察、任务边界、3 条历史、Git
工作区观察、候选进程观察、独立 AI 分析、中文展示、安全限制和非干扰性验收。

研发可按内部阶段推进，但在以上能力完成前不称为首个可用版本。受 Pi API 限制的
能力允许诚实降级为“未知 + 原因 + 可信度”，不允许用无证据推测冒充完整实现。

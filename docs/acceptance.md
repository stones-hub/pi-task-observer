# 首个可用版本验收标准

状态：已确认（2026-09-11）

## 1. 命令完整性

以下命令全部可用并具有中文帮助和错误提示：

```text
/status
/status help
/status timeline
/status files
/status analyze
/status history
/status <1|2|3>
/status <1|2|3> timeline
/status <1|2|3> files
/status <1|2|3> analyze
```

未知子命令、编号越界、顺序错误和多余参数均提示 `/status help`。不提供 `raw`、
`process` 或 `watch` 子命令。

## 2. 非干扰性

在模型 streaming、长时间 bash 和并行工具执行期间调用普通状态命令，必须证明：

- 当前 Agent 和工具没有被取消或暂停；
- 命令没有进入 steering/follow-up 队列；
- 没有触发主 Agent 的模型调用；
- 没有新增参与主模型上下文的消息；
- 没有修改被观察项目文件；
- `/status help` 不执行 Git、进程或 AI 查询。

`/status analyze` 只产生独立模型调用，主 Agent 的消息树、上下文和执行状态不变。

## 3. 生命周期和任务边界

真实或可重复的集成场景覆盖：

- 空闲时普通输入创建新任务；
- Skill/Template 输入创建任务；
- Steering 归入当前任务且不占历史名额；
- Follow-up 排队时不新建，实际作为后续 user turn 交付时成为新任务；
- 一个 `agent_start → agent_end` Run 跨越原任务与 follow-up 时，各任务记录同一 Run ID
  下不重叠的 Execution Segment，不强行伪造新的 `agent_start`；
- 多条 follow-up 在 `one-at-a-time` 下按每次实际交付分别建任务，在 `all` 下按一次合并
  交付批次建任务，并保留批次内各条来源；
- follow-up 边界证据不足时标记部分观测及原因，不仅凭文本猜测；
- 自动 retry、overflow compaction 和 retry 不错误拆成新任务；
- 正常结束、失败和 abort 进入历史；
- 并行工具状态不会互相覆盖；
- `/reload` 或中途加载明确显示观测不完整；
- Session replacement 不混淆旧、新 Session 状态。

## 4. 历史限制

- 当前活跃任务不计入历史 3 条；
- 每个 Session 最多显示最近 3 条已结束任务；
- 第 4 条按结束时间淘汰最早记录；
- 成功、失败、中止使用相同规则；
- 编号 `1` 始终代表最近结束的任务。

## 5. 工作区观察

至少覆盖干净仓库、初始 dirty、初始 modified 后再次修改、staged、unstaged、
untracked、删除、重命名、特殊字符路径、非 Git 仓库、Git 超时和大型文件预算。

输出必须区分基线已有变化、运行期间进一步变化和当前状态；任何场景都不得无证据
声称文件由当前 Agent 修改。

## 6. 进程观察

在 macOS（以及实现声明支持的平台）覆盖：

- 长时间 bash 存在唯一高可信候选；
- 子进程树含测试 worker；
- 多个并行 bash 导致多个候选；
- 工具仍未返回但候选已退出；
- 无权限、命令缺失和平台不支持；
- 模型/read/edit 阶段不显示误导性的独立进程。

PID 存活和父子关系作为事实展示；工具归属带可信度；不得将进程与文件修改做未经
证实的关联。

## 7. AI 分析

- 使用当前已配置模型的独立 completion；
- 输出中文，并包含阶段、依据、可能已完成、当前活动、可能剩余、风险/未知、置信度；
- 显著标注“AI 推断”；
- 输入不含完整环境变量、完整 diff、完整无界日志或明显凭证；
- 支持取消、超时、无认证、provider 错误和主任务同时运行；
- 若 usage/cost 可用则展示额外调用成本；
- 分析失败不影响观察器和主任务。

## 8. 中文与安全

- 用户可见标题、状态、解释、错误和帮助以中文为主；
- 工具名、命令、路径、PID、Session ID、Run ID 和原始错误保留必要英文；
- 内部枚举不会直接替代用户说明；
- 常见 Token、API Key、Authorization、密码和私钥模式经过测试确认被脱敏；
- 调试默认关闭且调试日志同样脱敏、截断。

## 9. 性能与稳定性

以下性能数字是在中小型 Git 仓库上的本机验收目标，不是所有机器和仓库的绝对
SLA；非干扰性以及 Git、进程、AI 失败时的局部降级是硬要求：

- `/status help` 近即时返回；
- 不含 AI 的 `/status` 在无 Git/进程慢操作时 P95 小于 100 ms；
- `/status files` 常规仓库 P95 小于 1 s；
- 进程快照目标小于 500 ms；
- Git、进程或 AI 超时只使对应区域降级，不使命令或 Agent 崩溃；
- 高频事件和长任务受固定容量约束，无无界内存增长。

## 10. 完成定义

首版只有在以下证据均具备时才可称为可用：

1. Pi 检查完整 diff 和范围；
2. 单元、集成与类型/静态检查通过；
3. 独立复审核查边界、并发、安全和 Pi API 使用；
4. 从真实 Pi TUI 加载 Extension；
5. 按本文件执行主任务运行中查询、Git 变化、长进程、AI 分析和历史淘汰场景；
6. 确认主任务未受干扰，结果中的事实、推断和未知边界正确；
7. README 安装和使用说明可由新用户复现。

# 任务目标

先通过真实 Pi 动态事件探针验证 v0.1 所依赖的生命周期和非干扰边界；仅在探针结果与
已确认方案相容时，完整实现、测试并本机验收 `pi-task-observer` v0.1 Pi Extension。

# Risk

- 类型：关键任务
- 判断理由：涉及并发事件聚合、主 Agent 隔离、独立模型调用、凭证脱敏、外部进程
  探测及 Git 状态语义；错误可能中断主任务、污染上下文或泄露敏感信息。
- 关键契约与升级触发条件：`/status` 旁路且普通查询不调用模型；不得修改被观察项目；
  事实、工作区、候选进程和 AI 推断分离；若动态探针显示 Pi 事件顺序或命令行为与
  `docs/design.md` 不相容，立即停止，不得静默改变产品语义或继续完整实现。Gate 1
  发现的 follow-up Run 边界差异已由用户于 2026-09-11 选择方案 A 解决：保留 follow-up
  新任务语义，允许一个 Run 跨任务并按实际交付 turn/batch 建立 Segment。

# Scope

- 当前基线：unborn `main`，无 HEAD；2026-09-11 编码前工作区全部为未跟踪的项目控制
  和方案文档：`AGENTS.md`、`HANDOVER.md`、`README.md`、`docs/`。任务书创建后再增加
  `.pi/tasks/001-v0.1-probe-and-implementation.md`。以编码 Agent 启动前
  `git status --porcelain=v1` 及仓库文件内容为实际未提交基线。
- 允许改动文件/目录：项目源码、测试、package manifest、锁文件、构建/测试配置、
  开发探针、`README.md`、`docs/`、`HANDOVER.md`、`.pi/tasks/`、必要的 `.gitignore`。
- 禁止改动文件/目录：`.git/`、仓库外文件、用户全局 Pi/Cursor 配置；不得把动态探针
  临时输出、凭证、完整 Prompt/响应/工具输出或本机绝对隐私数据加入仓库。

# 执行器与授权

- 执行器：Cursor
- 请求模型：`cursor-grok-4.6-high`（本机 `cursor-agent --list-models` 已确认可用；
  最终报告以 Cursor 响应能否证明实际模型为准）
- 编码授权：已于 2026-09-11 获得
- 权限范围：允许在当前工作区执行动态探针并编写正式源码和测试；不允许 commit、
  push、发布、部署、SSH、访问生产环境、修改全局配置或安装全局软件。

# 真实业务背景

用户需要在 Pi 主 Agent streaming、执行长命令或并行工具时，通过 `/status` 查看当前
任务状态，而不让查询成为 steering/follow-up 或主上下文消息。产品还需诚实呈现任务
期间观察到的 Git 变化、Pi 后代候选进程，以及仅由 `/status analyze` 触发的独立 AI
推断。完整需求、设计、限制和验收分别见 `docs/requirements.md`、`docs/design.md`、
`docs/feasibility.md`、`docs/acceptance.md`。

# 已确认的源码事实

- 当前尚无正式 Extension 源码、测试或 package manifest。
- Pi 官方 API 支持 Extension command、input/agent/turn/message/tool/compaction/session
  事件与 `ctx.modelRegistry.complete(...)` 独立调用。
- Extension command 在 input 事件前分派；`agent_end` 是低层 run 结束，
  `agent_settled` 表示没有自动 continuation。
- 内置 bash 工具事件不暴露子进程 PID；只能建立带证据等级的候选关联。
- Git 没有任务级原子快照 API，基线必须异步并标注完整性。
- 正式实现参数以 `docs/design.md` 第 10 节为准，包括 256 条事件、展示数量、文本限制、
  Git 预算、Git/进程超时、2 秒缓存及 AI 300 秒硬超时。

# 实施关卡

## Gate 1：动态事件探针

- 建立最小、明确可删除或仅保留在开发测试目录的事件探针与可重复说明。
- 在真实 Pi 中验证并记录：普通输入、steering、follow-up（含可行时的 one-at-a-time / all）、
  `before_agent_start`、`agent_start/end/settled`、并行工具、abort、compaction/retry、
  streaming/长 bash 期间 Extension command 响应，以及命令是否进入 input、消息树或上下文。
- 探针不得记录完整 Prompt、响应、环境变量或凭证；证据必须脱敏、有限且不提交临时日志。
- 若任何结果与已确认任务边界或非干扰契约不相容，停止并清楚报告，不进入 Gate 2。
- 若某些稀有事件（如真实 provider retry/overflow）无法安全稳定触发，标为未验证并说明，
  不伪造结论；是否构成 Gate 2 阻断按其对核心设计的影响判断并报告 Pi。

## Gate 2：完整 v0.1 实现

状态：用户已于 2026-09-11 确认 Gate 1 后方案 A，允许开始。

实现正式 Pi Extension package，优先使用 Pi 官方 API 与 Node.js 标准库，完整覆盖确认
方案；不得以 MVP 名义省略 Git、进程或 AI 能力。任务聚合必须采用更新后的 Run/Segment

# 预期正确行为

- 正常路径：加载即观察；正确聚合用户任务和 Execution Run；普通 `/status` 命令快速、
  中文、旁路显示；历史限制为当前任务加最近 3 条；Git、候选进程和 AI 分区工作；
  `/status analyze` 仅按用户命令独立调用当前模型。
- 关键异常/边界路径：并行工具不互相覆盖；steering 不新建任务；follow-up 实际执行时
  才新建；retry/compaction 不错误拆任务；reload/中途加载标记部分观测；非 Git、Git
  超时、进程命令缺失/无权限/不支持、模型缺失/无认证/取消/超时/provider 错误均局部
  降级；容量淘汰和预算降低精度必须明示；不得无证据归因文件或进程。

- 关键任务额外测试/独立复审：至少一路全新只读 review；测试必须覆盖命令解析、中文

  非 Git/超时/预算、进程候选与降级、脱敏/截断、AI 输入预算/隔离/取消/300 秒超时。

# Verify：本机候选运行验收

- 是否改变运行行为：是
- 运行方式：从当前工作区构建或由 Pi 正式 TypeScript Extension 入口加载；使用临时隔离
  Git 仓库和临时输出目录，真实 Pi TUI 为最终入口。
- 本地依赖及数据库类型/版本：Node.js/npm 与本机 Pi；无数据库、无生产服务。
- 构建或安装命令：以最终 `package.json` scripts 为准；不得全局安装。
- 启动命令：以 `pi -e <当前工作区 Extension 入口>` 或 package 本地路径加载；不得把
  未验收候选写入全局 Extension 目录。
- 业务就绪检查：Pi TUI 成功加载当前候选，`/status help` 和正式命令可调用，无启动异常。
- 正式入口和核心黑盒业务场景：真实 TUI 中在模型 streaming、长时间 bash、并行工具
  期间调用 `/status`；执行 timeline/files/history/编号/analyze；制造隔离 Git 变化、历史
  淘汰和候选长进程场景。
- 必须检查的最终结果：主任务和工具未取消/暂停；命令不进入 steering/follow-up、主消息
  树或主上下文；普通查询无模型调用；AI 调用独立；中文输出、事实/推断/未知边界、历史
  编号、Git 措辞和进程可信度正确。
- 必须检查的日志：Pi 启动/运行日志与显式安全调试日志（如启用），确认无未解释异常、
  无完整敏感字段及无无界输出。
- 关键失败/边界/恢复场景：非 Git、Git 超时/失败、进程探测失败、AI 取消或 provider
  失败、reload 部分观测；稀有且无法安全触发者记录受阻，不以模拟冒充真实验收。
- 停止和清理命令：退出测试 Pi；终止仅由本验收启动的长进程；删除临时仓库、日志和
  package 安装测试目录；不得清理用户既有进程或文件。
- 测试数据准备与清理：仅使用合成文本、临时 Git 仓库和无真实凭证环境。
- 禁止连接的域名、数据库和环境：除用户当前 Pi/Cursor 已配置的模型服务及项目本地
  npm 依赖安装所需 registry 外，不连接任何外部业务系统；禁止生产数据库、SSH 和目标机。
- 环境缺失时的阻断条件：无法启动真实 Pi TUI、无法加载当前 Extension、无可用测试模型
  导致 analyze 无法实测，或缺少所声明平台进程工具时，对应验收标记受阻，不得声称通过。

# 验收标准

- 完整满足 `docs/acceptance.md`，且默认参数符合 `docs/design.md` 第 10 节。
- `/status help` 静态、近即时且不触发 Git/进程/AI；所有非法语法中文提示 help。
- 普通命令不调用模型、不写 Session、不控制主 Agent、不修改被观察工作区。
- 每 Session 仅 1 个当前任务和 3 个历史；所有文本、时间线、文件指纹和 AI 输入有界。
- 所有外部命令均使用 argv、明确 cwd 和超时，不拼接未经处理的 shell 字符串。
- Git、进程和 AI 任一失败均只降级自身区块。
- 编码 Agent 自报、单元测试、进程存活均不能单独构成完成；必须由 Pi 完成 diff、测试、
  独立复审及真实 Pi TUI 黑盒验收。

# 禁止事项

- 禁止读取或输出凭证，禁止未经授权 SSH 或访问生产环境。
- 禁止未经单独授权 commit、push、发布或部署。
- 禁止 rsync、scp、docker cp 或其他绕开 Git 的代码交付。
- 禁止覆盖 Pi 内置工具、注册 LLM tool、调用主 Agent 控制 API，或用 `sendMessage`、
  `sendUserMessage`、`appendEntry` 实现状态查询/分析。
- 遇到范围冲突、前提错误、探针不相容或验证受阻时停止并报告，不静默改方案、降低标准
  或切换执行器。
